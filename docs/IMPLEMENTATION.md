# V1 开发说明

## 实现基线

以 `CDP_Lite_PRD.md` 与 `CDP_Lite_Technical_Architecture.md` 为唯一产品与架构基线。没有实现用户行为采集、计算引擎、成员数据、人群分发或 AI 生成功能。

| 阶段 | 实现内容 |
| --- | --- |
| 工程基座 | pnpm 工作区、React / Koa、数据库迁移、统一错误、请求 ID、页面导航 |
| 标签与属性 | CRUD、分页筛选、枚举值、数据类型 / 展示类型校验 |
| 行为模型 | 所属维度与指标、维度值、父子归属、跨表字段名唯一 |
| 规则领域 | 共享 Schema、操作符映射、值类型 / 日期校验、引用扫描 |
| 规则构建器 | 混合规则、二维数组 AND / OR、模型 / 时间前置条件、维度与聚合 |
| 人群管理 | 创建、回显、编辑、复制、删除、revision 冲突 |
| 验收配套 | 单元测试、MySQL 集成测试、浏览器 E2E、种子数据、OpenAPI |

## 本次采用的具体决策

1. **字段与显示配置**：String / Number 支持枚举；枚举字段使用 SELECT / MULTI_SELECT，非枚举字段使用其类型原生输入。展示类型可在兼容范围内调整，`isEnum`、`dataType`、技术编码创建后不可修改。
2. **表单方案**：统一 Ant Design Form，符合架构文档允许统一选择同等表单方案的约定。没有同时引入 React Hook Form。
3. **草稿**：草稿、已配置、停用人群都要求完整有效的规则；未完成条件可以留在当前页面，不能作为合法记录提交。遵循 PRD 至少一组、每组至少一条有效规则的保存约束。
4. **已停用引用**：历史 JSON 不被改写；回显仍保留 ID 和原值，并提示停用 / 缺失状态。重新保存与复制前需要修复这些无效引用。没有自动替换或删除条件。
5. **不可变属性**：字段 / 行为 / 人群技术编码、数据类型、枚举开关和规则版本不可变；枚举值编码只有未引用时才允许更新。名称、描述和状态可更新。
6. **COUNT**：事件发生次数的目标值限定为非负整数；其他数值指标支持有限小数。COUNT 的 metricId 固定 null。
7. **时间**：绝对时间必须包含时区且开始早于结束，Date 必须为真实日历日期。相对时间的未来执行锚点没有在 V1 求值。
8. **规模限制**：每个人群最多 20 组、每组 50 条规则、每条行为规则 30 个维度过滤、列表值最多 100 个，防止无界输入。相对天数最多 36500 天。
9. **写入一致性**：使用 MySQL 事务和固定锁行，覆盖所有 Service 写入。全局写锁作为轻量 V1 的保守实现，避免只依赖前端或单进程内存锁。
10. **认证模式**：统一身份上下文 `local-demo / administrator`，仅绑定回环地址。预留 Socket.IO 模块目录，不启动空转连接。
11. **演示数据**：种子脚本按技术编码幂等创建 11 个标签、14 个属性和 11 个行为模型，并补齐枚举值、事件维度与指标；不生成用户明细、行为事实或计算结果。

## 界面规范：企业业务工作台

以 `docs/UI界面风格参考.png` 为当前视觉基线，替代此前的 Calm Workspace 编辑式风格；业务与数据契约保持不变。目标为紧凑、理智、简约，将主要空间交给列表与配置：

- `apps/webapp/src/styles/theme.ts` 统一定义 `workspaceTokens`，映射 CSS 变量与 Ant Design 主题。采用深色顶栏、浅灰工作区、白色业务面板、蓝色操作链接、2px 圆角，不增加装饰卡片或动效。
- 顶栏 52px、上下文侧栏 180px、桌面工作区边距 12px；常规控件 32px、手机主要控件 40px。正文 14px，页面标题 16px；密度主要来自间距和结构调整，而非缩小正文。
- 顶部仅保留已实现的人群与元数据模块；侧栏随模块切换。不仿造参考图中尚未实现的人群计算、洞察、分发或分类能力。
- 列表标题与工具栏紧邻表格；名称改为单行，描述保留在名称悬停提示和编辑表单中。桌面操作列固定右侧，窄屏可水平滚动查看所有字段与操作。
- 移除英文眉题、介绍段落、页脚和独立规则概览。规则数量、JSON 入口合并到规则工具栏；AND / OR、计算边界与不可变字段说明以短标签或提示呈现。错误、删除确认和未保存状态保留。
- 1024px 以下使用导航抽屉，保留背景隔离、键盘焦点循环、Esc 关闭及焦点恢复；规则表单在窄屏单列重排。
- `e2e/workspace-ui.spec.ts` 覆盖 320 / 390 / 768 / 1280 / 1440px、桌面十行列表首屏可见与行高限制、减少动态效果、导航与 JSON 抽屉，以及加载 / 空 / 错误重试 / 字段校验状态。截图输出到 `test-results/`。

UI 状态测试仅在模拟加载与服务失败时拦截请求；业务流程和多视口样本仍使用真实 API 与隔离 MySQL，并清理自身创建的数据。

## 后续可确认事项

这些是后续产品选择，不影响当前明确需求的闭环：

- 是否允许把不完整规则持久化为“草稿”，以及草稿与引用保护的对应策略。
- 是否允许字段从非枚举转枚举；如允许，需要独立迁移流程，不能通过普通 PATCH 隐式改变语义。
- 若需要修复停用引用之外仍可保存描述，是否允许“历史无效规则”状态或仅基础信息编辑。
- 如需面向公网或多人开放，确认身份认证、会话与权限需求后再扩展受控演示模式。

演示数据与测试数据使用不同 MySQL 容器和端口。没有以 Mock 接口替代持久化验收。
